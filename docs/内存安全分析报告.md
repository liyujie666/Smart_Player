### 2.1 音频模块 — SDL 回调线程与主线程竞争 `audio_buf_`

**文件：** `audiooutput.cpp`
**行号：** 136–192
**严重性：** **High**
**类型：** 数据竞争 / 内存错误

**问题描述：**

`audiooutput.cpp` 中，`Init()` 方法在**主线程**中重新分配 `audio_buf_`：

```123:136:audiooutput.cpp
if (audio_buf_) {
    free(audio_buf_);   // 主线程：释放旧缓冲区
    audio_buf_ = nullptr;
}
audio_buf_ = (uint8_t*)realloc(audio_buf_, newSize);  // 主线程：分配新缓冲区
```

与此同时，SDL 音频回调 `fill_audio_pcm()`（运行在**SDL 音频线程**）持续访问和写入 `audio_buf_`：

```283:286:audiooutput.cpp
void AudioOutput::fill_audio_pcm(void *udata, Uint8 *stream, int len)
{
    AudioOutput* self = (AudioOutput*)udata;
    self->resampleFrameToBuffer(stream, len);  // SDL 线程持续读写 audio_buf_
}
```

`realloc` 不是原子操作。当主线程调用 `realloc` 释放旧块、分配新块时，SDL 线程可能正在通过 `memcpy(stream, audio_buf_ + audio_buf_index_, copy_len)` 读取旧缓冲区或写入已被 `realloc` 移动的内存。这会导致：

- **读已释放内存**：SDL 线程读取到已被 `free` 的旧块
- **写野指针**：SDL 线程通过旧的 `audio_buf_` 指针写入已被 `realloc` 移动的新块，而新块的内容可能已被其他线程覆写
- **双重释放**：`realloc` 内部会 `free` 旧块，如果 SDL 线程持有指向该块的指针，后续访问触发未定义行为

**修复方案：**

在 `Init()` 的重分配路径加锁，并在 `DeInit()` 和 `fill_audio_pcm` 中使用同一把锁：

```cpp
// audiooutput.h 中
QMutex audio_buf_mutex_;  // 新增成员

// audiooutput.cpp Init() 中
{
    QMutexLocker lock(&audio_buf_mutex_);
    if (audio_buf_) {
        free(audio_buf_);
    }
    audio_buf_ = (uint8_t*)realloc(audio_buf_, newSize);
    // ...
}

// fill_audio_pcm 中
void AudioOutput::fill_audio_pcm(void *udata, Uint8 *stream, int len) {
    AudioOutput* self = (AudioOutput*)udata;
    if (!self || !self->is_audio_init_) return;
    QMutexLocker lock(&self->audio_buf_mutex_);
    self->resampleFrameToBuffer(stream, len);
}
```

### 2.2 渲染模块 — `makeCurrent`/`doneCurrent` 配对失衡

**文件：** `openglrenderer.cpp`
**行号：** 多处
**严重性：** **High**
**类型：** 资源泄漏 / OpenGL 上下文错误

**问题描述：**

多处 `makeCurrent()` 调用与 `doneCurrent()` 数量不匹配：

1. **uploadSubtitleTexture 早期返回路径**（约 line 210-216）：
   ```cpp
   makeCurrent();              // +1
   // ... 一些检查 ...
   if (subtitleTexture_) {
       subtitleTexture_->destroy();
       delete subtitleTexture_;
       subtitleTexture_ = nullptr;
   }
   // 🔥 如果此时 break/return，doneCurrent() 永远不会被调用
   doneCurrent();              // 正常退出路径
   ```

2. **uploadRGBATexture** 中调用了两次 `makeCurrent()`（约 line 196）：
   ```cpp
   makeCurrent();              // 第1次
   // ...
   if (rgbTexture_) { rgbTexture_->destroy(); delete rgbTexture_; }
   // ...
   makeCurrent();              // 第2次（第1次之后的某处）
   // ...
   doneCurrent();              // 只调用一次
   ```
   每次 `makeCurrent()` 必须有对应的 `doneCurrent()` 调用。两次 `makeCurrent()` 只有一次 `doneCurrent()` 会导致 OpenGL 上下文栈不平衡。

**修复方案：**

使用 RAII 封装或确保所有代码路径都调用 `doneCurrent()`：

```cpp
void OpenGLRenderer::uploadSubtitleTexture(const QString& text) {
    makeCurrent();
    QMutexLocker locker(&subtitle_mutex_); // RAII 自动在析构时 unlock
    // 但注意：makeCurrent/doneCurrent 仍需配对
    // 推荐使用 QOpenGLContext::currentContext() 检查
    // ...
    doneCurrent();
}
```

### 2.3 渲染模块 — `sync_clock_` 生命周期问题

**文件：** `audiooutput.h` 第 64 行，`audiooutput.cpp` 第 186–187 行
**严重性：** **High**
**类型：** 悬空指针

**问题描述：**

`AudioOutput` 持有 `AVSyncClock* sync_clock_` 原始指针，并在 `resampleFrameToBuffer` 中直接解引用：

```186:187:audiooutput.cpp
// audio_clock_us_ = av_rescale_q(frame->pts, audio_timebase_, {1, 1000000});
sync_clock_->set_audio_clock(audio_clock_us_);  // 🔥 解引用 sync_clock_
```

`sync_clock_` 由外部（`PlayerCore`）创建并管理生命周期。如果 `PlayerCore` 先于 `AudioOutput` 析构，或在播放中途重新初始化 `AudioOutput` 而不更新 `sync_clock_` 指向，则 `AudioOutput::resampleFrameToBuffer` 会解引用一个悬空指针。

**修复方案：**

使用 `QPointer<AVSyncClock>`，或在 `AudioOutput` 中增加 `sync_clock_` 的空检查：

```cpp
// audiooutput.h
QPointer<AVSyncClock> sync_clock_;  // 自动在对象删除时置空

// audiooutput.cpp
if (sync_clock_) {
    sync_clock_->set_audio_clock(audio_clock_us_);
}
```

### 2.4 App 模块 — previewplayer 跨线程访问 `demuxer_`/`decoder_`

**文件：** `previewplayer.cpp`
**行号：** 全部
**严重性：** **High**
**类型：** 跨线程访问

**问题描述：**

```cpp:27:28:previewplayer.cpp
PreviewPlayer::PreviewPlayer(QObject *parent) : QObject(parent)
{
    workThread_ = new QThread(this);
    this->moveToThread(workThread_);  // 所有公开 slots 运行在工作线程
    workThread_->start();
}
```

- `open()` 方法在**主线程**中被调用，直接访问 `demuxer_` / `decoder_`（由 `release()` 在主线程中 `delete`）
- `decode()` 运行在**工作线程**中，同时访问同样的 `demuxer_` / `decoder_`
- 没有任何互斥锁保护这两个对象的并发访问
- 当主线程调用 `stop()` → `release()` 时，工作线程可能正在 `decode()` 中使用这些对象

**修复方案：**

在 `PreviewPlayer` 中增加线程安全机制：

```cpp
private:
    QMutex decoder_mutex_;
    QMutex demuxer_mutex_;
```

在 `open()`、`release()`、`decode()` 中使用这些锁。

### 2.7 Core 模块 — resampler_ 缺失删除导致内存泄漏

**文件：** `playercore.cpp`
**严重性：** **High**
**类型：** 内存泄漏

**问题描述：**

`PlayerCore` 中 `resampler_` 通过 `new` 创建但未在析构函数中 `delete`。在视频流切换（`closeInternal()` → `openInternal()`）时，旧 `resampler_` 泄漏。在多次切换视频后，内存持续增长。

**修复方案：**

在 `PlayerCore` 析构函数中添加：

```cpp
PlayerCore::~PlayerCore() {
    // ... 其他清理 ...
    if (resampler_) {
        delete resampler_;
        resampler_ = nullptr;
    }
}
```

### 2.12 Decoder 模块 — init() 持有写锁时递归调用

**文件：** `decoder.cpp`
**行号：** 36–76
**严重性：** **High**
**类型：** 逻辑错误 / 潜在死锁

**问题描述：**

```cpp:36:37:decoder.cpp

    // ...

        if (ret < 0) {
```

递归调用 `init()` 时，外层 `QWriteLocker` 尚未释放（锁在函数返回时才释放）。虽然当前递归路径不会再获取锁（因为 `hwType` 为 `NONE` 会走软件路径），但此模式脆弱——任何对 `init()` 的修改都可能引入死锁。

**修复方案：** 重构为非递归：

```cpp
int Decoder::init(AVCodecParameters *codecpar, AVMediaType type, const QString &decodeName)
{
    QWriteLocker locker(&lock_);
    closeInternal();

    if (!codecpar) return AVERROR(EINVAL);
    mediaType_ = type;

    AVHWDeviceType hwType = AV_HWDEVICE_TYPE_NONE;
    bool tryHardware = useHardware_.load() && mediaType_ == AVMEDIA_TYPE_VIDEO;
    if (tryHardware) {
        hwType = getBestHardwareType();
    }

    const AVCodec* codec = findDecoder(codecpar, hwType, decodeName);
    if (!codec) {
        qCritical() << "未找到合适的解码器";
        return AVERROR_DECODER_NOT_FOUND;
    }

    codecCtx_ = avcodec_alloc_context3(codec);
    if (!codecCtx_) return AVERROR(ENOMEM);

    int ret = avcodec_parameters_to_context(codecCtx_, codecpar);
    if (ret < 0) { closeInternal(); return ret; }

    if (tryHardware && hwType != AV_HWDEVICE_TYPE_NONE) {
        ret = initHardware(hwType);
        if (ret >= 0) {
            codecCtx_->get_format = Decoder::hwPixFmtCallback;
            codecCtx_->hw_device_ctx = av_buffer_ref(hwDeviceCtx_);
        } else {
            // 🔥 软解回退，不需要递归！直接继续
            useHardware_.store(false);
            closeInternal();
            // 重新走一遍软解路径（使用局部变量，不再递归）
            return initSoftware(codecpar, type, decodeName);  // 调用独立的软件初始化函数
        }
    }

    ret = avcodec_open2(codecCtx_, codec, nullptr);
    if (ret < 0) { closeInternal(); return ret; }

    isOpened_ = true;
    return 0;
}

// 独立的软件解码器初始化（无锁，因为调用者已持有锁）
int Decoder::initSoftware(AVCodecParameters *codecpar, AVMediaType type, const QString &decodeName)
{

    codecCtx_ = avcodec_alloc_context3(codec);

    int ret = avcodec_parameters_to_context(codecCtx_, codecpar);
    if (ret < 0) { closeInternal(); return ret; }

    ret = avcodec_open2(codecCtx_, codec, nullptr);
    if (ret < 0) { closeInternal(); return ret; }

    isOpened_ = true;
    return 0;
}
```
