基于当前代码的冗余现状，我认为**最合理专业的 ASR 字幕架构**应该把"音频从哪来"和"音频怎么识别"彻底解耦，让识别管道只有一份，并做到**时间对齐 + 可取消 + 可缓存**。下面是我的设计。

## 一、设计原则

1. **单一职责**：音频源只产 PCM，识别管道只吃 PCM，渲染只消费结果。
2. **管道一份**:VAD→ASR→翻译 只实现一次，离线/实时都复用。
3. **时间锚定**：每条字幕带**绝对媒体时间戳**，字幕才能跟随播放、随 seek 跳变。
4. **可中断**：识别是长任务，`stop`/seek 必须用协作式取消令牌，不能靠杀线程。
5. **配置驱动**：引擎/语言/翻译都来自 `ConfigManager`，代码里不散落 `if(Whisper)`。

## 三、关键接口（伪代码）

```cpp
// 音频源：只负责产出归一化 PCM + 媒体基准时间
struct PcmChunk { std::vector<float> samples; double mediaTimeSec; };
class IAudioSource {
public:
    virtual bool open(const MediaInfo&) = 0;
    virtual PcmChunk pull() = 0;            // 阻塞直到有数据/EOF
    virtual bool eof() const = 0;
    virtual void cancel() = 0;              // 协作式中断
};

// VAD 流式优先：离线可一次性喂完, 实时逐块喂
class IVadEngine {
public:
    virtual void feed(const float* pcm, size_t n, double t0) = 0;
    virtual std::vector<VadSegment> flush() = 0;  // 吐出完整语音段
};

// ASR：识别一段 PCM, 返回文本 + 词级时间戳(用于精细对齐)
class IAsrEngine {
public:
    virtual SubtitleItem recognize(const float* pcm, size_t n,
                                   const RecognizeOptions&) = 0;
};
```

`AsrPipeline::run(IAudioSource* src)` 大体就是：
```
while (!src->eof()) {
    auto [pcm, t0] = src->pull();
    vad->feed(pcm, n, t0);
    for (seg : vad->flush())                 // 完整的语音段
        item = asr->recognize(seg.pcm, opt); // 带 t0+seg.offset
        if (translate) item.translated = translator->translate(item.text);
        queue->push(item);
}
```

## 四、相对当前代码要收敛的点

| 现状 | 目标 |
|------|------|
| 两个策略各写一套 demux→decode→resample→VAD→ASR→翻译 | 抽出 `IAudioSource`，管道逻辑全归 `AsrPipeline` |
| `AsrOfflineStrategy`/`AsrRealtimeStrategy` 承载全部管道 | 退化为 `FileAudioSource`/`LiveAudioSource` 两个适配器 |
| Whisper 复用分支散在 3 处 | 下沉进 `WhisperEngine` 自身（引擎管自己的 context 缓存） |
| `AsrManager` 半接入 `AsrPipeline`（有 `buildPipelineConfig` 死代码） | 删除死代码，`switchMode` 只选 source + 把 source 交给 pipeline |
| "实时字幕"按钮本地文件却走离线 | 按钮改名"字幕识别"，source 由 `mediaType` 自动选 |

## 五、几个专业加分项

1. **词级时间戳**：Whisper/SenseVoice 都能出 token 级时间，用它们做字幕起止，屏上同步更准，比"整段 30s 窗口"体验好很多。
2. **离线结果缓存**：按"文件 hash + 引擎 + 语言"存磁盘字幕缓存，重开同一文件秒出（类似 YouTube 字幕），避免重复算力。
3. **背压/限流**：`SubtitleQueue` 设上限，消费者慢时 pipeline 节流或丢最旧，避免内存暴涨。
4. **协作式取消**：`IAudioSource::cancel()` + pipeline 检查取消令牌，`stop`/seek 即时响应，不靠强杀线程。
5. **错误与降级**：某引擎加载失败自动降级（如 SenseVoice 故障回退 Whisper），并上报而非崩溃。

---

这套架构的本质就是：**把"音频源"抽象成唯一变量，其余管道全共享**。当前代码离这步只差"抽出 `IAudioSource` + 让 `AsrPipeline` 真正接管"，改动量中等。
